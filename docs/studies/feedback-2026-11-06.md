# Editor and viewer feedback (2026-11-06)

The maintainer tried the editor, the viewer, kiosk mode and the admin pages
after the UI redesign and the Nine IX style work, and sent 42 points. This
note keeps every point (numbered P1 to P42, translated from French) and
groups them into tasks F1 to F15, in the order they should be done. Each
task is one roadmap line in [ROADMAP.md](../ROADMAP.md) "Not started" and,
unless it says otherwise, one thread and one pull request.

Screenshots sent with the feedback are in
[feedback-2026-11-06/](feedback-2026-11-06/).

## Rules that apply to every task

- **The whole map lives in its `.conf` file** (P21). Anything a task adds to
  the map (legend boxes, free boxes, focus areas, cluster groups, zone shapes,
  fonts, label arrows...) is written in the `.conf`, with a `SET` hint when
  there is no keyword for it, and is read back by the PNG and SVG renderers.
  Only per-user things (shortcuts, savepoint list, panel state) live
  elsewhere.
- English code and UI, French added in the same change (translation files).
- Each task updates the README and moves its roadmap line to "Recently done".

## Answer to P33: View and Preview

*View* (`/map/{id}`) is the live viewer: the map drawn as SVG, with zoom,
hover cards, side panel, site focus and playback. *Preview* is the older
mode: the PNG picture of the map with an HTML image map for tooltips. It is
what kiosk mode, *Open as PNG* and the maps page *Preview* still use. Task F7
removes this split: everything shown on screen becomes SVG, and the PNG is
only made when someone downloads it.

## Tasks, in order

### F1. Editor quick fixes (bugs)

Small, independent fixes in the SVG editor.

- P5. When a change is being saved, the *Saving…* text pushes the top bar
  to the right. Give the save state a fixed width (or put it where its
  length does not move anything).
- P6. Ticking or unticking *Show the legend on the map* shows *Hidden* /
  *Shown* one step late, so the label is wrong. The label must follow the
  box state at once.
- P11. The grid cannot be seen on a dark background and barely on a light
  one. Draw it with a colour that contrasts with the map background (and
  the basemap), for example a light or dark line chosen from the background
  luminance, with a bit more opacity.
- P14. The shape choices in the selected node's panel (*Box*, *Rounded box*,
  *Circle*) are raster pictures and look pixelated. Draw them as SVG (icon
  sprite or inline SVG).

### F2. Admin pages polish

- P39. Import review page (`/admin/migration/...`): add *Compare old and
  new* and *Convert again* at the top of the page, not only at the bottom,
  because the page can be very long.
- P42. Admin > *Kiosk mode*: add *Cancel* and *Save* at the top as well,
  for long pages (same pattern as P39; consider a sticky action bar for
  every Settings panel).
- P41. Tighten the admin pages: rows of tables and the space between other
  items are a bit too tall. Reduce the vertical padding (tokens), keep touch
  targets usable on phones.
- P40. Move the *Maps & rendering* settings from `.env` into the app (stored
  in the database, edited in Settings > Maps & rendering). `.env` stays only
  as the first default, or for what must be known before the database is
  open. Today the page shows the `.env` values read only.

### F3. Map items: legends, link speed and timestamps in the editor

- P4. There is no way to add the *Link speed* legend seen on the *ISP
  backbone* demo map ([link-speed-legend.png](feedback-2026-11-06/link-speed-legend.png)).
  It exists in the renderer (`SET width_legend x y`, `SET width_legend_title`,
  `DrawWidthLegend`) but the editor has no control for it. Add it to the
  *Add* panel and to the map panel, like the other legends.
- P7. Clicking *Link speed*, *Link load* (legend) or *Updated* (timestamp)
  on the map selects it, but Delete does nothing: the only way is to untick
  it in the right menu. Delete (key, selection bar, context menu) must remove
  them (hide them in the `.conf`), with undo.

### F4. Link labels in the editor

- P1. With the *A bar next to the selection* layout, the command that moves
  overlapping link labels apart (*Move bandwidth labels that overlap*,
  `untangle`) cannot be found: it is only in the `Ctrl+K` search and the
  movable toolbars. Put it in the selection bar (and the ⋯ menu).
- P23. Untangle only the selection when there is one (labels of the selected
  links), and add the same for nodes: move overlapping nodes of the
  selection apart.
- P24. Even after untangling, some labels still overlap
  ([untangle-leftovers.png](feedback-2026-11-06/untangle-leftovers.png): the
  two labels between Lyon and Marseille, the label under GR, labels on the
  parallel links near Paris). The current algorithm only slides a label
  along its own link, in one pass, and keeps it where it was when no free
  spot is found; it also ignores node labels and badges drawn at their
  basemap size. Improve it: several passes, try the other label of the same
  link and parallel links, allow a small offset across the link, use the
  boxes as drawn, and report the labels it could not place.
- P2. There is no way to turn link labels on or off. Add *Labels* (on/off,
  and which value) to the link panel for the selection and to *Link
  defaults* for the whole map (`BWLABEL none` and its friends).
- P20. Moving a link label with the mouse: there is a drag handle on the
  labels of a selected link, but it is not discoverable and does not seem to
  work in every case (pill labels, basemap). Make it work on hover without
  selecting first, with a move cursor.
- P3. Links without an arrow head, with the arrow on the label instead, as
  on https://stats.nine-ix.net/: a link style with no arrow head (flat ends)
  combined with the pill label arrow (#64). Per link and in *Link defaults*.

### F5. Link ends and hover highlight

- P35. Link ends must always be hidden under the node they connect to
  ([link-ends-past-node.png](feedback-2026-11-06/link-ends-past-node.png):
  the ends of several thick links stick out around a badge node). Draw
  links under nodes everywhere (PNG, SVG, editor, viewer, clusters) and end
  or clip each link at the node's edge.
- P17. After routing a link with right angles (#43), there is no way back to
  a straight segment. Add *Straight* to the routing choices (removes the
  `VIA` points), per segment if possible.
- P26. Invert the glow around links: no glow at rest, the glow appears when
  the pointer is on the link (`SET link_glow` behaviour in the viewer).
- P31. Every map element (node, link, zone, legend, note, box) shows its
  outline with the same small soft glow when the pointer is on it, in the
  editor and in the viewer.

### F6. Editor navigation and keyboard shortcuts

- P9. `Ctrl` + drag on the background should pan the map. Today `Ctrl` +
  drag duplicates (#26). Proposal, to avoid two meanings for one shortcut:
  drag on the background = marquee selection (unchanged); `Ctrl` + drag,
  `Space` + drag or middle button drag on the background = pan; `Alt` + drag
  on a node or a selection = duplicate (as in Figma and Inkscape); `Ctrl` +
  drag on a selected node keeps duplicating for a while, with a hint. The
  final choice is the maintainer's; list it in the shortcuts dialog.
- P25. A page in the user's profile to manage keyboard shortcuts: list every
  shortcut by area, change one, detect conflicts, reset one or all. Saved
  per user (database), read by the editor, the viewer and the command
  palette.

Done in F6 with the proposal of P9 as defaults: `Ctrl` + drag on the
background pans, `Alt` + drag duplicates, `Shift` while dragging turns the
snapping off (it was `Alt`), `Ctrl` + drag on a node still duplicates for a
while with a hint. Each of the three drag keys can be changed per user on
the shortcuts page (P25), so the maintainer can pick other defaults in
`App\Services\KeyboardShortcuts::ACTIONS`.

### F7. Viewer, kiosk and preview: SVG everywhere

- P29. The preview is not drawn as SVG. Show the SVG, and make the PNG only
  for *Download PNG*.
- P36. Kiosk mode must use the SVG maps.
- P34. From the live view, *Copy kiosk link* opens a kiosk without the
  background picture. Fix it, and add *Download as SVG* next to *Download
  PNG*.
- P33. Merge *View* and *Preview* (see the answer above): one viewer, the
  PNG as a download.
- P37. In the live view side panel, collapse or expand every site at once
  ([sites-panel.png](feedback-2026-11-06/sites-panel.png)): one button in
  the panel header, remembered in the browser.
- P38. A popup box (hover card pinned, site card, menus) closes on a click
  outside it.

### F8. Boxes on the map: legends, totals and free boxes

Depends on F7 (kiosk in SVG). The viewer side panel (#70) already has the
total traffic and the colour legend; this task lets the map author place
boxes on the map itself, shown in live view, kiosk, PNG and SVG, movable in
the editor and saved in the `.conf`.

- P32. Legends on the map, in the style of the live view panel, movable.
  Box types: *Total traffic* (value and small graph), *Traffic legend*,
  *Free box* with formatted text and rows (like Nine's *Points of presence*,
  [nine-points-of-presence.png](feedback-2026-11-06/nine-points-of-presence.png),
  rows can be fed from the map: sites with their node count or load),
  *Link speed* (P4) and *Updated at*.
- P30. A load bar in Nine's style that can be placed on the map: a
  gradient bar with 0 % and 100 % ([nine-traffic-gradient.png](feedback-2026-11-06/nine-traffic-gradient.png)).
  This is the *Traffic legend* box above drawn with the gradient of F10.
- P38 applies to boxes shown as popups.

### F9. Editor panels: map settings and colour picker

- P13. *Map settings* opens another page and leaves the editor. Show it in
  the editor's right panel (or as the drawer over the editor, like on the
  Maps page), without leaving the editor.
- P18. The colour picker looks like a Windows XP dialog. Replace it with a
  picker in the app's style (tokens, both themes): swatches of the map's
  colours and the theme, a hue/saturation area, hex field, recent colours,
  *none*.

### F10. Themes and link load gradient

- P19. More themes in the library (map themes like *Night*), so users have a
  choice, with a shared design base (same type scale, spacing, legend and
  label styles) so they stay coherent.
- P28. A theme for the *link load* scale with a smooth gradient instead of
  blocks of colour, like https://stats.nine-ix.net/ (link colour taken from
  the gradient at the link's load, legend drawn as a gradient bar).

### F11. Fonts

- P27. A modern default font, open source (OFL or similar), that can follow
  curved links (#55 needs a vector font), in the spirit of the Nine IX map.
  Ship it and make it the default for new maps and the *Night* theme.
- P16. Nodes, legends, zones and the rest only offer the built-in fonts.
  Offer every shipped font for each object. Add a map-wide font setting that
  applies one font to every text of the map, after a confirmation (it
  overwrites per-object fonts); after that, each object can still get its
  own font.

### F12. Zones

- P15. Change a zone's shape (rounded corners with a radius, maybe other
  shapes), and move the zone's label with the mouse, as for node labels.

### F13. Savepoints and timestamped history

- P12. Savepoints, or a timestamped history, to go back quickly to a state
  after a test, in the style of the VS Code *Timeline*
  ([vscode-timeline.png](feedback-2026-11-06/vscode-timeline.png)): a list
  of the map's saved versions with their time (relative, exact on hover),
  named savepoints the user creates, preview and restore of a version
  (restoring is itself a new version, so it can be undone). Builds on
  `ConfigHistory` (#63).

### F14. Focus areas

- P22. Put the focus on parts of a map, also in kiosk mode: on a broad map,
  one area that is more critical stands out (the rest dimmed or smaller, or
  the kiosk zooms on it). Saved in the `.conf`. Can reuse the site focus
  dimming of #69.

### F15. Geographic maps in the editor: zoom, clusters and site size

- P10. On the *France sites* map, the live view can zoom into the sites but
  the editor cannot. Allow zooming the editor the same way, and give three
  cluster modes: group nearby sites (today's behaviour), no grouping, or
  groups the author defines (shown grouped). Site size must be adjustable in
  the editor, per site, and stay proportional when zooming; today sites are
  smaller in the viewer than in the editor, and the two must match.
