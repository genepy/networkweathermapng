# Viewer and editor feedback (2026-11-13)

After F1 to F15 were merged (up to #100), the maintainer sent ten more
points on the live viewer and the editor. This note keeps every point
(numbered P43 to P52 after the 42 points of
[feedback-2026-11-06.md](feedback-2026-11-06.md), translated from French),
adds four leftovers noted by earlier threads (P53 to P56), and groups them
into tasks F16 to F26, in the order they should be done. Each task is one
roadmap line in [ROADMAP.md](../ROADMAP.md) "Not started" and, unless it
says otherwise, one thread and one pull request.

Screenshots sent with the feedback are in
[feedback-2026-11-13/](feedback-2026-11-13/).

The rules of the 2026-11-06 note still apply: the whole map lives in its
`.conf` file (P21), code and UI in English with French added in the same
change, and each task updates the README and moves its roadmap line to
"Recently done".

## Tasks, in order

### F16. Link ends at nodes in the live viewer (bug)

- P43. The link ends fix of F5 (links stop at the node instead of running
  past it) works in the editor but not in the live view: in the viewer,
  links still do not end cleanly on their nodes
  ([live-link-hover-zoomed.png](feedback-2026-11-13/live-link-hover-zoomed.png),
  ends at *Paris La Defense* and the nodes at the top and bottom).

Acceptance: the same map shows the same link ends in the editor, the live
viewer (at 100 % and zoomed, with and without a basemap), the kiosk and the
SVG download. Find why the viewer path differs (SVG built by the server vs
redrawn or re-projected in the browser by `geo-view.js`, node size kept on
screen while zooming) and fix it there, with a test on the SVG output.

### F17. Link hover halo proportional to the link width

- P44. When the pointer is over a link, the halo drawn around it becomes
  very large when the map is zoomed in
  ([live-link-hover-zoomed.png](feedback-2026-11-13/live-link-hover-zoomed.png)).
  The halo must stay proportional to the width of the link.

Acceptance: at every zoom level (editor and viewer, with and without a
basemap) the halo is a fixed ratio of the link width as drawn on screen
(for example the width plus a small margin), never a fixed size in map
units that grows with the zoom, and never thinner than the link.

### F18. Link flow animation: one dot per link, full width

- P45. The dots that move along links to show traffic must be as wide as
  the link, and there must be only one at a time on each link, as on the
  Nine IX map ([nine-link-flow.png](feedback-2026-11-13/nine-link-flow.png):
  one light spot crosses each link).

Acceptance: the flow animation draws a single moving spot per link (per
direction half for two-way links), whose width matches the link width at
every zoom; its speed can still follow the load. Reduced motion still turns
it off.

### F19. Map items and boxes: one modern design, removable from the menu

- P46. The *Map items* (legends, link speed, timestamp, F3) and the *Boxes*
  (F8) partly duplicate each other. Merge them into one set of map items
  with a more modern design, for example like the Nine IX *Traffic* box
  ([nine-traffic-box.png](feedback-2026-11-13/nine-traffic-box.png): title,
  gradient bar, 0 % and 100 %, small credits line, rounded dark card). An
  item must be removable from the map from its entry in the menu (a click
  on it there, not only selecting it on the canvas).

Acceptance: one list of item types in the editor, without two ways to add
the same legend, speed or timestamp; existing maps that use the old
keywords or `SET box_*` hints still load and render the same content (map
the old form to the new one on read, keep it in the `.conf`); the new card
design is used in PNG, SVG, viewer and kiosk, light and dark themes; each
item in the editor menu has a remove action. Update the demo maps.

### F20. Untangle labels keeps them on their links

- P47. *Untangle labels* must keep each label on its own link: labels are
  only spread apart along the link when there is room between the two
  nodes, never moved off the link.

Acceptance: after *Untangle labels*, every bandwidth label still sits on
its link line (its position stays a fraction along the link); overlapping
labels are spread along the link when the link is long enough, and left in
place when it is not. Test on a map with short and long links.

### F21. Links without arrows or one-way: colour of the busiest direction

- P48. When the link shape has no arrows, or shows only one direction, the
  link must take the colour of its busiest direction (today one half is
  drawn per direction, or one direction wins arbitrarily;
  [labels-zoomed-one-way.png](feedback-2026-11-13/labels-zoomed-one-way.png)).

Acceptance: for the no-arrow and one-direction shapes, the whole link is
coloured with the scale colour of `max(in %, out %)`, in PNG, SVG, viewer
and kiosk; the hover card still shows both directions. Unit test in the
engine.

### F22. Bandwidth labels sized with the zoom

- P49. Bandwidth labels must stay proportional to the zoom: today, when the
  map is zoomed in, they become huge
  ([labels-zoomed-one-way.png](feedback-2026-11-13/labels-zoomed-one-way.png)).

Acceptance: in the viewer and the editor, zoomed in on a map with or
without a basemap, labels keep a size in proportion to the links and nodes
around them (or a fixed screen size, whichever matches the link widths of
F15); they never cover the nodes they belong to. F15 hides them very deep
in: keep that.

### F23. Ctrl+A selects map objects only

- P50. In the editor, Ctrl+A must select only the objects of the map, not
  the text of the menus and panels.

Acceptance: with the focus on the canvas or anywhere outside a text field,
Ctrl+A selects every node, link, zone, note and map item and the browser
does not highlight the page text; inside a text field, Ctrl+A still selects
the field's text. The shortcut is listed on `/account/shortcuts` (F6).

### F24. Tooltips that explain the editor options

- P51. Add tooltips (info bubbles) that explain the options in the editor
  menus, for example *Shape* > *Arrow*: what *Both directions* and *One
  direction* mean.

Acceptance: every choice whose effect is not obvious from its name has a
short explanation shown on hover and on keyboard focus (an *i* button or
the native tooltip), for at least link shape, arrow style, label style,
label position, cluster mode, focus area style and background sizing. The
texts are in the translation files (English and French).

### F25. Choose and place the viewer panels

- P52. In the viewer, the author can choose which panels are shown (*Sites*,
  *Total traffic*, *Link load* legend, and the date of the last update) and
  where they are placed ([viewer-side-panel.png](feedback-2026-11-13/viewer-side-panel.png)).

Acceptance: map properties have a *Viewer panels* section listing each
panel with a show/hide switch and a position (side panel, top left, top
right, bottom left, bottom right, or its order in the side panel); the
choice is written in the `.conf` with `SET` hints and used by the viewer and
the kiosk; maps without the hints look as today.

### F26. Leftovers from earlier tasks

Small fixes noted by earlier threads, one pull request.

- P53. In the editor, Ctrl+Shift+drag on empty space pans the view instead
  of adding a rectangle selection to the current selection (F6).
- P54. The fullscreen viewer page (`?fullscreen=1`) does not load
  `shortcuts.js`, so the user's custom shortcuts do not work there; only Esc
  does (F7).
- P55. The link *Label style* choice *Custom text (--)* probably has the
  same bug as the custom arrow size fixed in #90: check it and fix it the
  same way (`MapEditor` accepts the value, the panel shows it, Link defaults
  lists it).
- P56. Housekeeping: the branch `claude/project-thread-8dbqxd` was waiting
  for deletion; it is gone from the remote on 2026-11-13, so nothing is
  left to do. Also check that the "Stale branches" table of the roadmap only
  lists branches that still exist.

Acceptance: each point has a test or a screenshot in the PR.
